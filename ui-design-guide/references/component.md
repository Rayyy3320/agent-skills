# 组件

用户要把一个组件做到极致时，力气全部集中在这一个对象上：它放大看也经得起，用起来有手感，放进任何产品都认得出。页面上的方法照常有效，但流程不同：方向少做，深度多做。

## 先写它回答的那个问题

用一句话写下用户看这个组件时最想知道或最想做的一件事，用用户的话写。例如行李追踪组件是“我的箱子到哪了”，不是“显示物流状态”。这句话决定谁是主角。

再写组件的构成，每项一两行：

- **主角**：用户最怕错过、会随时间变化的那个量，例如还要等多久、还剩多少。它在组件里最大、最先被看到。
- **陪衬**：判断主角需要的其他信息，越少越好。
- **主操作**：只有一个。写清它的手感：拖、按、长按还是滑；拖动时会不会吸附到常用值。
- **状态**：确定本次任务涉及的默认、操作中、完成、失败和边界状态，例如加载、暂停、0、满或超长名称。设计应让用户看出相关状态的区别，不只做漂亮的默认状态；主视觉承担状态信息时，明确它的哪一层随之改变，三层见下一节。
- **容器**：它会出现在哪些尺寸里，例如整页卡片、小组件、通知栏。没要求时只做一种。

## 先定主视觉，再画组件

组件也需要一个视觉主角，不能只靠文字、数字和进度条撑起来。按顺序找：

1. **实物**：组件背后有实物时，用它的写实渲染或产品照片。透明底，角度和光线按组件的版式定。组件的主色从实物里取：外壳、配件或内容里最认得出的那种颜色。实物只有银灰黑白时，可以把颜色交给它身上一个会亮的部位，并让它随状态变化。生成提示词里写明这个颜色和这个部位。组件本体里，主视觉要么完整放下，要么明确设计成出血到组件边缘，不能被容器随意切掉一角。
2. **数据画成的量**：没有实物时，把主角画成看得见的量：面积、长度或个数。见 [设计方向](design-direction.md) 的“让人记住的一刻”。

需要的图先按 [素材](media.md) 生成或选好，再围绕它排版。组件的颜色从这张图里取两三种：主色是图里最有辨识度的颜色，其余靠黑白灰。先定色板再去配图，图和界面会像两样东西。

主视觉分三层，生成图之前先分好：

- **主体层**：实物本身。离散状态可以复用同一张图的变体，保持角度、光向和大小一致；比例、部件或色泽需要连续跟手变化时，按 [素材](media.md) 选择多层次矢量或实时渲染，静态图保留作氛围与质感。生成提示词见该文件的“写提示词”。
- **画在上面的层**：用代码画的线、量和标注，贴在实物上这个量发生的那个部位。它随数据实时变，是状态变化的主要落点。
- **背景层**：组件底色和实物身后的光。例如等待中光线变暗，出错时光熄掉，完成时亮起。这是状态的意思，不是装饰。

主操作是调一个量时，这个量只画一条尺：不要上面放一条只读进度条，下面又放一条调节滑块。主视觉上的刻度、圆环或进度条能直接拖，就让当前值和目标显示在同一条尺上，常用值做成尺上的吸附刻度；主视觉是写实照片、看不出哪里能拖时，留一条清楚的操控尺，拖动时照片同步变化，不另画第二条尺。

同一个数字不要在文字里到处写。做完默认状态后看一遍每个数字出现在哪几处：精确读数配直观图形、快捷档位按钮或尺上的常用刻度各有用途；但如果同一个当前值或目标值既写在标题里、又写在滑块旁、底下说明再写一遍，没有新增信息或操作用途，就删到只剩最有力的那一处。

需要判断主视觉能否区分状态时，可以暂时忽略文字与数字，比较相关状态的图形和背景变化。它是辅助判断方法，不要求生成遮字图；必要的文字、数值和可访问标签仍应保留。

再定一个母题：一种从产品里来的图形，从主视觉一路用到进度、加载、主按钮和开关。一个组件里只用一种母题。母题同时决定控件的形状：圆的母题推出圆的控件，直的推出直的，细的推出细线边框。下半部分如果退回组件库默认的按钮和开关，整个组件就只有上半部分是设计；底部的说明小字保持干净易读即可，不必硬套图形。

大数字是组件的脸。按组件的气质给它选数字字体，系统字体或项目既有字体贴合时也可以用，等宽或比例字形按 [视觉语言](visual-language.md) 选；标签用另一款安静的字。两款够了。

## 方向少做，深度多做

1. **按需比较草图。** 默认直接深化一个有依据的方向；用户要求比较或重要分歧确需画面判断时才制作必要的候选。只做默认状态的静态画面，不写交互、不取证。草图之间在主视觉、母题和主操作的手感上不同，不是同一个布局换颜色。放进 [风格对比页](style-explorer.md) 给用户挑；用户让你自己决定时，选最有辨识度、又最能回答那个问题的一张，写下理由。
2. **选定后只深化这一个。** 实现任务要求的状态与主操作，按受影响问题精修，不自动扩展到所有状态或多轮评审。其他草图不再深化。

## 把一处做到极致

组件的记忆点通常在主操作发生的那一刻。按本次操作选用下面的手感；需要记录时同步已有设计说明：

- **跟手**：拖动时，被拖的东西和手指之间没有延迟；跟着变化的数字、颜色、主视觉同步变化，不等松手。
- **阻尼和吸附**：经过常用值（例如 80%、100%）时有一次轻微的停顿，松手后吸附过去；拖过头会被拉回来。
- **结果当场发生**：调了目标，主视觉跟着变，而不是只改一个数字。
- **数字的变化**：连续调节时与主视觉同步；需要显示过程时再用滚动或插值，保持位宽稳定。需要精确判断的读数不因动画变得难读。
- **状态之间的过渡**：从发生变化的地方出发。

动效的时长和曲线见 [动效](motion.md)。只在主操作和关键状态切换上用力，其余保持安静。

## 按需精修

先查看本次涉及的组件与关键状态，检查主信息、操作反馈和可读性。只有细节无法在正常尺寸判断时取放大图；只有动作时序需要检查时取录屏。不默认生成遮字图、全状态并排图或独立评审。

用户要求独立评审时，提供当前任务、约束和必要画面，反馈具体问题及影响。修复后只复核受影响部分，不使用默认分数门槛或固定轮次。

## 交付

交付用户要求的组件或设计稿，说明相关状态与交互的验证结果。作品图、并排状态图和录屏仅在用户要求或能解释关键结果时提供，不作为默认交付门槛。

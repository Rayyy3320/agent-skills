# 评审手册：横向对比、任务走查、方案评审与复核

评审者专用，是 [评审手册](reviewer-manual.md) 的补充。主 Agent 派发时会写明按哪一节执行。

## 1. 多方向横向对比（查重）

同时看所有方向的截图（首屏或整页），只回答一个问题：哪些区块在不同方向里本质上是同一个东西（骨架和版式相同，只是换了颜色和字体）？逐个点名，要求退回按各自的方向重做。

## 2. 任务走查（纯交互与 UX）

如果不看截图，而是操作真实页面/高保真原型：
1. 顺着真实任务走，记录每一步看到了什么、为什么点这里。
2. 标记三类问题：**卡住**（走不下去）、**走错**（点错又退回）、**犹豫**（需要猜）。
3. 检查异常：能否原地恢复失败（断网/空数据）。会保存东西的产品，再走刷新后读回、保存失败时是否如实告知并能重试；谎报成功、刷新丢数据是严重问题。游戏类另按 [游玩验收](play-craft.md) 的“交付和评审时多查几项”。
4. 声音、触觉和真机手感没法验证时，写明未验证，不当作通过。
5. **输出要求**：按严重程度排序提交体验障碍报告。不打审美分。

## 3. 改流程与加新功能方案评审

比较多个交互方案：
1. 指出是否存在入口和步数都相同、纯粹是换了画面的假差异方案。
2. 指出哪一步还在让用户伺候界面（找入口、重复填已知值、为了确认而确认）。
3. 找出表面上的“补丁”设计（加了提示但没减少用户麻烦）。
4. **输出要求**：指出每个方案最可能失败的场景。不打分。

## 4. 复核（已有问题修复后按需使用）

主 Agent 交来新截图和上一轮的问题与提升清单。你的任务是核对，不是从头再评一遍：

1. 逐条判断上一轮的问题和提升：**修好**、**修了一部分**或**没修**，提升按做到位、做了一部分或没做来写，每条写一句新截图里看到的证据。只认画面：主 Agent 说修好了不算数，截图里看不出来的算没修；只是挪了位置、改了数值，问题本身还在的，算修了一部分。
2. 对照上一轮的“保留”一行，看那一处有没有被这批修改磨掉。磨掉了算新问题。
3. 这批修改带来的新问题最多写 3 条，按 [评审手册](reviewer-manual.md) 第 1 节的标准判断。上一轮没提过的老问题不在这一轮补，之后要不要另派全新评审由主 Agent 决定。新问题和“离下一档还差什么”里不写“再加一样”；只是对象变少、主角没有变大变强的减法，算修了一部分。
4. 截图明显不是当前版本时，只写这一点，不打分。核对某条问题需要的画面没给（例如某个状态），那条记为“无法核对”，不因此停评。
5. **输出要求**：说明核对结果、证据和本次引入的相关问题；用户明确要求评分时再提供分数，不默认追逐下一档或新增评审轮次。
